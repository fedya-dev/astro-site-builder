# Astro Site Builder

**Интерактивен Bash генератор за бързо създаване на самостоятелен двуезичен блог с Astro.** Генерира чист проект, който можеш да редактираш, проверяваш и публикуваш самостоятелно — без CMS и без зависимост от генератора след създаването му.

## Възможности

- Генериране на самостоятелен статичен блог с Astro.
- Български и английски маршрути и локализирани интерфейсни елементи.
- Два визуално различни дизайна: **Midnight** и **Ocean**.
- Превключване между светъл и тъмен режим.
- Markdown/MDX статии чрез Astro Content Collections.
- Автоматично съдържание (TOC) от заглавия H2/H3.
- Локално филтриране на статиите, категории и тагове.
- SEO метаданни, canonical URL, Open Graph/Twitter metadata, JSON-LD и `hreflang`.
- RSS емисии, `robots.txt`, Sitemap и favicon файлове.
- Примерни статии, директория `public/images/` и ръководство за редактиране на основните файлове.

## Изисквания

- Linux, macOS или Ubuntu под WSL2.
- Node.js 20 или по-нова версия; препоръчва се актуална поддържана LTS версия.
- npm.
- Интернет връзка за инсталиране на npm зависимостите.

## Инсталиране и стартиране

Клонирай хранилището или изтегли ZIP архива и влез в директорията на проекта. След това изпълни:

```bash
chmod +x astro-site-builder.sh
./astro-site-builder.sh
```

Генераторът ще поиска:

1. Път към новата директория на сайта.
2. Заглавие на сайта.
3. Основен URL адрес.
4. Визуална тема — `Midnight` или `Ocean`.

Избери празна директория. Генераторът отказва да презапише файлове в непразна директория. След копиране на шаблона той инсталира зависимостите и стартира production build. Ако инсталацията или build процесът прекъсне, влез в генерираната директория, разреши показаната грешка и изпълни необходимите npm команди ръчно.

Полезни опции на самия генератор:

```bash
./astro-site-builder.sh --help
./astro-site-builder.sh --version
```

## Работа с генерирания сайт

В директорията на създадения сайт:

```bash
npm run dev       # локален сървър за разработка
npm run check     # диагностика на Astro и TypeScript
npm run build     # проверка и production build в dist/
npm run preview   # локален преглед на production build
```

## Добавяне на статии и изображения

Създай файл например `src/content/blog/linux-saveti.md`:

```yaml
---
title: "Полезни съвети за Linux"
seoTitle: "Linux съвети за ежедневна работа"
description: "Кратко описание за резултатите от търсенето и списъците със статии."
pubDate: 2026-10-10
category: "Linux"
tags: [Linux, Bash]
lang: bg
draft: false
heroImage: "/images/linux-saveti.webp"
heroImageAlt: "Описание на изображението"
---

Текстът на статията се пише в Markdown.
```

Задължителни полета: `title`, `description` и `pubDate`. `lang` е `bg` или `en`. Статии с `draft: true` не се публикуват в production build. Българските статии се генерират под `/blog/`, а английските — под `/en/blog/`.

Поставяй изображенията в `public/images/` и използвай URL като `/images/linux-saveti.webp`. Изображението трябва да е включено в проекта, за да се появи след публикуване.

Допълнителни frontmatter полета включват `seoTitle`, `translationKey`, `updatedDate`, `category`, `tags`, `heroImage`, `heroImageAlt` и `author`. За свързване на преведени статии използвай еднакъв `translationKey` в българската и английската версия.

## Езици, теми и конфигурация

- Български маршрути: `/`, `/blog/`, `/categories/`, `/tags/`, `/about/`.
- Английски маршрути: `/en/`, `/en/blog/`, `/en/categories/`, `/en/tags/`, `/en/about/`.
- Съдържанието не се превежда автоматично — създава се отделна статия за всеки език.
- Превключвателят за език отвежда към началната страница на другия език, а не автоматично към превода на текущата статия.

Файлът `site.config.json` управлява основните настройки:

```json
{
  "type": "blog",
  "defaultLang": "bg",
  "title": "Моят сайт",
  "site": "https://example.com",
  "design": "midnight"
}
```

- **Midnight** — тъмна визия с ярък зелен акцент.
- **Ocean** — синьо-зелена визия със светъл фон по подразбиране, градиенти и по-заоблени елементи.

И двете теми поддържат светъл и тъмен режим. Преди публикуване задай `site` на реалния публичен HTTPS адрес, защото той се използва за canonical URL, RSS и Sitemap. Не оставяй локалния адрес в production конфигурацията.

За да разбереш кой файл променя менюто, футъра, цветовете, SEO или TOC, виж [CUSTOMIZATION.md](CUSTOMIZATION.md).

## SEO, RSS и Sitemap

- `/rss.xml` съдържа статии на езика, зададен в `defaultLang`; `/en/rss.xml` съдържа английските статии.
- RSS връзката и надписът ѝ се съобразяват с езика на текущата страница.
- Статиите генерират JSON-LD `BlogPosting`, а началните страници — `WebSite`.
- `hreflang` се генерира за съответстващите статични маршрути и за статии със същия `translationKey`.
- `@astrojs/sitemap` генерира Sitemap по време на production build.
- `src/pages/robots.txt.ts` генерира `robots.txt` с връзка към Sitemap.
- Favicon файловете се копират от `public/` в крайния build.

След успешен build можеш да провериш резултатите с:

```bash
ls -la dist/sitemap-index.xml dist/robots.txt dist/favicon.svg dist/favicon.ico dist/apple-touch-icon.png
```

## Проверки

Провери Bash синтаксиса и изпълни вградените smoke тестове от корена на хранилището:

```bash
bash -n astro-site-builder.sh
bash tests/test-builder.sh
./astro-site-builder.sh --version
```

Smoke тестовете проверяват структурата на генератора и ключови регресии, но **не заменят** `npm run check` и `npm run build` върху реално генериран сайт. Преди да приемеш промени, създай тестов сайт в празна директория и провери и двата дизайна, BG/EN маршрутите, статия с изображение, RSS и build резултата.

## Публикуване

Генерираният сайт е статичен и може да се публикува в Cloudflare Pages или друг статичен хостинг. Обичайните настройки за Cloudflare Pages са:

- Build command: `npm run build`
- Output directory: `dist`

След първата успешна инсталация запази `package-lock.json` в Git, за да могат CI/CD процесите да използват `npm ci` за възпроизводима инсталация.

## Ограничения

- Генераторът създава само Blog проект; Portfolio и Hybrid режими не се поддържат.
- Това не е CMS. Статиите се редактират като Markdown/MDX и промените изискват нов build и deployment.
- Автоматичен превод между български и английски няма.
- Проверявай реалния production build преди публикуване; smoke тестовете сами по себе си не гарантират работоспособност на всеки генериран сайт.
